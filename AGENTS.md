# AGENTS.md

Operating contract for every agent working in this repository.

## Project

`kernel-tailor` is a Rust workspace that probes hardware, generates a Kconfig
plan, builds a uniquely named kernel package, and verifies it before blessing it.
The CLI is `kt`. Arch Linux / Omarchy is the first target. V1 does not patch
kernel source.

## Current state

This is a scaffold. There is no Cargo workspace yet. TASK-001 creates `kt-core`
with human approval. Do not invent crates, modules, APIs, symbols, or sysfs paths
that are not in your task card or verified local source.

## Read order

1. `AGENTS.md`
2. `docs/architecture.md`
3. `docs/contracts/*.md`
4. your task card in `docs/tasks/`
5. only the files in your allowed edit list

## Hard rules

- One task per session. Read the task card before any edit.
- Edit only the files listed under **Allowed files**. If you need another file,
  stop and report; do not widen your own scope.
- Never edit the root `Cargo.toml`, `rust-toolchain.toml`,
  `.github/workflows/**`, `opencode.jsonc`, `.opencode/agents/**`, or `LICENSE*`.
  These are human-owned. A crate-level `Cargo.toml` may be edited only when the
  task card lists it and every dependency in it is already approved by an ADR.
- Never hand-edit `Cargo.lock`. If a cargo command updates it, report the diff;
  the reviewer and the human see it before merge.
- Never add a dependency without an ADR and explicit human approval.
- Never run `sudo`, `su`, `doas`, `pacman -U`, `mkinitcpio`, `limine`,
  `efibootmgr`, `bootctl`, or anything that writes to `/boot` or the running
  kernel.
- Never run `git push`, `git reset --hard`, `git clean -f`, or `rm -rf`.
- Never spawn subagents. Report to the lead.
- No `unsafe` Rust. The workspace will forbid it.
- Redact fixtures: no serials, MACs, UUIDs, hostnames, usernames, IPs, or tokens.
- Keep diffs small. If a task exceeds roughly 400 lines or two crates, stop and
  report.

## Verify before claiming

- **Kconfig symbols:** `rg "config SYMBOL"` in the kernel tree; cite `file:line`.
  A plausible-sounding symbol is not a symbol.
- **Kernel modules:** check `modinfo`, `modules.alias`, or `modules.builtin`.
- **Sysfs paths:** inspect the live machine or a committed fixture.
- **Crate APIs:** read local source or `cargo doc`; do not guess.
- **Commands:** run the task's acceptance commands and report exact results.
  "Should work" is not a result.

## Handoff

Return exactly:

```
STATUS: done | blocked
TASK: <id>
BRANCH: <branch>
FILES: <paths>
COMMANDS:
  <command> -> <exact result>
CONTRACT IMPACT: none | <change>
DECISIONS: <bullets>
OPEN QUESTIONS: <bullets>
RISKS: <bullets>
```

Do not paste long logs. Save them under `target/agent-logs/<task>/` and return
only the key lines.

## Sources of truth

1. The local kernel tree and live sysfs.
2. `docs/contracts/` and committed fixtures.
3. Upstream documentation (the researcher must cite URL and date/commit).
4. Never a plausible memory.

## Definition of done

- Every acceptance command passes.
- Tests cover the new behavior and at least one failure mode.
- Fixtures are redacted and deterministic.
- No out-of-scope files are touched.
- The verifier reports PASS and the reviewer reports no blocking findings.
- The task card and `docs/status.md` are updated.
