# Build plan contract

Status: draft. Authoritative schema will be generated by `kt-core` in TASK-001.

A plan is the deterministic result of applying hardware requirements and a policy
profile to a base kernel config. It must explain every decision.

## Top-level shape

```json
{
  "schema_version": 1,
  "manifest_sha256": "...",
  "base_config": {
    "source": "/proc/config.gz",
    "kernel_release": "7.2.15-1-omarchy",
    "sha256": "..."
  },
  "profile": "balanced",
  "decisions": [
    {
      "symbol": "CONFIG_DRM_AMDGPU_SI",
      "old": "y",
      "new": "n",
      "action": "disable",
      "reason": "No SI/CIK GPU present; Phoenix2 is RDNA3",
      "provenance": {
        "detector": "gpu.amd",
        "requirement": "gpu:1002:15c8",
        "policy": "gpu.amd.disable-legacy-si-cik",
        "kconfig": "drivers/gpu/drm/amd/amdgpu/Kconfig:31"
      },
      "risk": "low",
      "status": "applied"
    }
  ],
  "conflicts": [
    {
      "symbol": "CONFIG_FOO",
      "intent": "disable",
      "result": "y",
      "selected_by": "CONFIG_BAR",
      "action": "reported"
    }
  ],
  "boot_linter": {
    "status": "pass",
    "findings": []
  },
  "estimates": {
    "modules_built": 287,
    "module_bytes": 18400000,
    "firmware_bytes": 4200000,
    "initramfs_bytes": 18000000
  }
}
```

## Requirements

- Every decision has a reason and provenance; anonymous changes are invalid.
- `status` is `applied`, `reported`, `blocked`, or `skipped`.
- A `select` conflict is reported, never hidden.
- Boot-critical findings block the build.
- Estimates are estimates; actual artifact sizes are measured after the build.
- The plan is reproducible from `manifest_sha256 + base_config + profile + tool version`.

## Profiles

- `safe`: keep hotplug classes, all common filesystems, debug facilities.
- `balanced` (default): trim hardware-specific drivers and unused debug features
  with workload guards.
- `aggressive`: trim legacy GPU support, unused compute stacks, camera/audio
  IP blocks, and firmware; requires explicit opt-in and recovery plan.

## Open questions for TASK-001

- How to represent `m` vs `y` transitions and their boot impact.
