# Report contract

Status: draft. Authoritative schema will be generated by `kt-core` in TASK-001.

A report explains what changed, why it is safe, and what was measured. It must
separate **kernel build changes** from **BIOS/runtime recommendations**.

## Sections

1. **Summary** — hardware, profile, base kernel, build identity.
2. **Hardware** — CPU, GPU, storage, network, boot chain.
3. **Config diff** — per-symbol old → new, reason, provenance, risk.
4. **Boot safety** — linter results, initramfs contents, firmware coverage.
5. **GPU** — VRAM/GTT usage, UMA pressure warning, IP blocks, firmware subset,
   compute runtime, driver options.
6. **Build** — artifact sizes, module count, warnings.
7. **Verification** — QEMU and real-boot results, dmesg errors, missing firmware.
8. **Measurements** — boot time, memory, benchmarks, baseline comparison.
9. **Recommendations** — BIOS/runtime actions that the tool cannot apply.

## Rules

- No unmeasured performance claims. If it was not benchmarked, say "not measured".
- Every removal has a reason and a risk level.
- Boot-critical failures are blocking and prominent.
- Redaction is checked before rendering; reports may be shared publicly.
- A "recommendation" is clearly not an applied change.
- Baseline comparison names the stock kernel version and the test conditions.

## GPU-specific requirements

For integrated GPUs, report:

- dedicated VRAM total and used, GTT total and used;
- monitor resolution/refresh if available;
- UMA carve-out warning when VRAM is small relative to the display;
- Mesa/Vulkan renderer and version;
- ROCm/HIP presence before suggesting HSA removal;
- whether HDMI/DP audio uses HDA or ACP;
- whether a MIPI camera or ISP is present.
