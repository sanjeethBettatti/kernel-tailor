# Hardware manifest contract

Status: draft. Authoritative schema will be generated by `kt-core` in TASK-001.

A manifest is a deterministic, redacted snapshot of one machine. It is the only
input the planner needs besides the base config and a policy profile.

## Requirements

- **Deterministic:** sorted keys/arrays, stable timestamps in fixtures.
- **Redacted:** no serials, MACs, UUIDs, hostnames, usernames, or IPs.
- **Versioned:** `schema_version` increments on semantic change.
- **Attributable:** every fact has a probe source; derived facts say so.
- **Small:** omit unrelated devices and noisy per-device attributes.

## Open questions for TASK-001

- Exact CPUID field names and microarchitecture mapping.
- Whether to store raw `modalias` strings or pre-parsed tuples.
- How to represent multiple GPUs and compute runtimes.
- Stable fixture timestamps: omit or normalize.
